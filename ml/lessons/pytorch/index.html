PyTorch 训练循环

前面所有概念，在代码里就是那七行。

前面九课把零件讲完了：模型是一堆参数，损失把「错得多离谱」压成一个数， 梯度告诉你参数该往哪边挪，反向传播是算梯度的那套流程。 现在要把这些零件装进一段能跑的代码。

循环体一共七行：搬数据、前向、算损失、清梯度、反向、更新参数、把损失累加起来打印。 去掉搬数据和统计这两行，剩下五个调用是 PyTorch 的固定套路：forward → loss → zero_grad → backward → step。zero_grad 写在 forward 之前也一样， 它只要排在 backward 前面就行。你在 GitHub 上看到的绝大多数训练脚本， 剥掉日志、断点续训、分布式包装之后，中心都是这五个调用。 换成 ResNet、换成 GPT 预训练、换成机器人策略，变的是模型和数据，这五个调用不变。

这一课不教新的数学。它要解决的是另一类问题：为什么漏掉一行不报错但结果是错的、 为什么验证集上的准确率每次都不一样、为什么训练跑到第三个轮次（epoch）就 OOM。 这些坑全都藏在这几行的细节里。

发生了什么

七个必须搞清楚的细节

下面每一条都是真实项目里反复出现的错误。它们的共同点是不报错， 所以只能靠理解提前避开。

1. Dataset 管「第 i 个是什么」，DataLoader 管「怎么取」

这两个类的职责是分开的。Dataset 只需要回答两个问题： 一共多少个样本（__len__），第 i 个样本长什么样（__getitem__）。 它不知道 batch 是什么，也不知道要不要打乱。

DataLoader 负责组织：生成下标顺序（shuffle=True 时打乱）、 按 batch_size 分组、把一组样本用 torch.stack 拼成一个张量、 用多个子进程提前把下一批准备好（num_workers）。 演示里 800 条训练数据、batch 32，所以内层循环走 25 次；验证集 200 条走 7 次， 最后一次只有 8 条——最后一个 batch 通常不满， 这就是为什么统计平均损失时要按样本数加权，而不是按 batch 数除。

2. 写 model(x)，不写 model.forward(x)

nn.Module 定义了 __call__。model(x) 走的是 __call__，它的顺序是： 先跑所有注册过的 forward pre-hook，再调 forward，再跑 forward hook。 直接调 model.forward(x) 会跳过前后两轮 hook。

在一段单机裸训练脚本里，两种写法输出完全一样，所以这个错误可以潜伏很久。 它咬人的时候通常是：你用 register_forward_hook 抓中间层特征， 结果什么都没抓到；或者用 DistributedDataParallel， 它的梯度同步就是挂在 hook 上的，绕过去之后多卡不同步； 或者做量化、剪枝、torch.fx 追踪，这些工具全都依赖 hook。

3. 梯度是累加的，所以必须 zero_grad()

loss.backward() 执行的是 p.grad += 新算出的梯度， 不是 p.grad = 新算出的梯度。漏掉清零，第 k 步用的梯度是前 k 步梯度之和。用 SGD 时这相当于步长随训练步数一路变大： 前几步损失还会正常下降，然后突然发散——这个失败模式很像「学习率设大了」， 很容易查错方向。

演示脚本用的是 Adam，症状不一样。Adam 的分母是梯度平方的滑动平均再开根号， 梯度整体放大 k 倍时分母也放大差不多 k 倍， 两边约掉，步长量级基本不变，所以往往不发散。变的是方向： 每一步的更新里混着前面所有步的旧梯度，模型最后停在一个明显更差的点上。 损失曲线看着还在下降，只是降不到该有的位置，比直接发散更难发现。

累加是设计出来的，不是 bug。显存装不下大 batch 时，可以用小 batch 连续 backward 几次再 step 一次，等效于大 batch。这叫梯度累加（gradient accumulation）， 下面代码那节有一段可以直接抄的实现。

另外，PyTorch 2.x 里 zero_grad() 的默认行为是 set_to_none=True：把 .grad 置为 None 而不是填满 0。省一次写显存，也让「这个参数这轮到底有没有梯度」变得可以区分。 副作用是你自己读 p.grad 时要先判空。

4. train() 和 eval() 只翻一个布尔开关

这两个方法做的事非常少：递归遍历所有子模块，把 self.training 设成 True 或 False。它们不冻结参数，也不关梯度。 真正读这个开关的只有少数几种层：

  • Dropout：True 时以概率 p 随机置零并把剩下的除以 1−p；False 时是恒等映射，什么都不做。
  • BatchNorm：True 时用当前这一批的均值方差做归一化， 并顺手更新滑动统计量；False 时用累计的滑动统计量，且不再更新。

所以忘记切 eval() 有两个后果：Dropout 还在随机丢， 同一批验证数据跑两次得到两个准确率；BatchNorm 用验证批的统计量归一化， 并且把验证集的统计量写进了 running_mean—— 这是一种真实的信息泄漏。反过来，验证完忘记切回 train()， Dropout 一直关着，正则化失效，训练损失会比该有的低，验证损失却不动。

5. torch.no_grad() 省的是中间激活的显存

前向时 autograd 会把每一步的中间结果留着，因为反向要用（第 09 课）。 这部分显存和网络深度、batch 大小成正比，训练时往往比参数本身还大。no_grad() 告诉 autograd「这段不用建图」，中间结果算完就丢。

它和 eval() 是两件正交的事：eval() 管层的行为，no_grad() 管建不建图。 验证时两个都要写。反过来，如果你在做对抗样本、需要对输入求梯度， 那就得开 eval() 但不能用 no_grad()。

6. .item() 与 .detach()

  • .item() 把只含一个元素的张量变成 Python 的 float 或 int。元素多于一个会报错。它会强制 GPU 同步， 也就是 CPU 停下来等 GPU 把这个数算完。
  • .detach() 返回一个新张量：同一块存储、同样的形状和设备， 但 requires_grad=False，也不再是计算图的一部分。

训练里累加损失必须用其中之一。total += loss 会让 total 一直引用着整条计算图（computational graph）， 一个 epoch 25 个 batch 的图全都释放不掉， 显存曲线一路上涨直到 OOM。这是初学者最常见的显存泄漏， 现象是「第一个 epoch 好好的，第二个就炸了」。

.item() 的代价是每次都要同步一次 GPU：CPU 必须停下来等这个数算完， 排队中的后续 kernel 也就发不出去。小模型上这个开销占比不可忽略。 真在乎速度时，把每步的 loss 攒进一个张量列表，整个 epoch 结束再一次性取回。

7. device 搬运：模型搬一次，数据搬无数次

model.to(device) 是原地改的，因为参数在模型内部注册着，to() 直接替换它们。张量不一样：x.to(device) 返回一个新张量，原来的 x 一动不动。 所以必须写 x = x.to(device)，只写 x.to(device) 是一行没有任何效果的代码，而且不报错。

数据一定是一批一批搬的。把整个数据集提前搬上 GPU 只在数据小的时候可行—— 演示里 1000 个二维点确实可以，但换成 ImageNet 就是 150GB。

还有一条顺序上的习惯：先 model.to(device)，再建优化器。 原因不是「否则动量会建在 CPU 上」——Module.to() 换掉的是参数对象内部的 .data，参数对象本身没换， 优化器持有的引用仍然有效，Adam 的动量是第一次 step() 时按参数当前所在设备建的， 所以顺序反了通常也能跑通。但这是实现细节，PyTorch 文档明确要求先搬后建， 照着写不吃亏。

为什么这些坑都不报错
上面七条里，只有第 7 条的 device 放错会抛异常（它的近亲 dtype 不匹配也会）。 其余六条要么是「代码照常跑完，结果不对」，要么是「跑着跑着 OOM」。 原因是 PyTorch 是命令式的：它按你写的顺序执行，不做全局检查， 也不知道你「本来想干什么」。这换来了调试时的灵活（可以随便下断点、随便 print）， 代价就是这类静默错误只能靠读代码发现。

梯度累加：显存装不下 batch 128 时，用 batch 32 连着 backward 四次再 step 一次。 四次累加出来的 .grad 和一次 batch 128 算出来的完全相同， 前提是损失先除以累加次数，否则梯度会是正常值的四倍。 代价是每次参数更新要跑四次前向和反向，一步更新的耗时大约变成四倍。

它有一个失效条件：模型里有 BatchNorm 时不等价。BatchNorm 用的是当前这一批的均值方差， 四个 32 条各自归一化的结果，和 128 条一起归一化的结果不是一回事。 这种情况下要换成 SyncBatchNorm、GroupNorm 或者 LayerNorm。

延伸

这一课要带走的一句话

forward → loss → zero_grad → backward → step，就是第 02 课那句「减去学习率乘梯度」换了个写法。

PyTorch 没有在数学上加任何新东西。它加的是工程约定：Dataset 和 DataLoader 分工取数、training 开关切换 Dropout 和 BatchNorm 的行为、.grad 累加以便做梯度累加。这些约定带来的坑基本都不报错， 所以只能提前知道。下一课把模型换成卷积网络，外面这层循环一个字都不用改。
