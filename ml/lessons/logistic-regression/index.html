逻辑回归

把直线的输出压进 0 到 1，直线就变成了一条分界线。

一笔信用卡交易刷出来，风控系统要判断它是不是盗刷。这看上去是个「是 / 否」的问题， 但真正有用的输出不是「是」，而是「这笔是盗刷的概率是 0.93」。 有了概率，下游才能分档处理：0.9 以上直接拒付，0.5 到 0.9 发短信让本人确认， 0.5 以下放行。只给一个「是」，这些档就没法分。

上一课的线性回归输出的是任意实数，可能给出 1.7，也可能给出 −0.3。 这两个数当概率都讲不通。逻辑回归（logistic regression）的做法是在线性部分后面 接一个函数，把整条实轴压进 0 到 1 之间。「写出模型 → 定义损失 → 梯度下降」 这三步的结构和上一课一样，换掉的是输出的值域和损失的具体形式。

它还是神经网络的直接前身：一个只有输入层和输出层、输出层用 sigmoid 激活的网络， 就是逻辑回归。第 08 课的神经元和这里的公式一字不差。

发生了什么

这里面到底发生了什么

图上有三样东西，它们表达的是同一个模型的不同侧面。

  • 概率热力图：平面上每个位置都有一个 p， 也就是模型认为「这个位置的样本属于类别 1」的概率。这才是模型真正的输出。
  • 决策边界：p=0.5 的那条等值线。 把概率变成类别，需要额外挑一个阈值，默认取 0.5，但这个 0.5 是人定的，不是模型算出来的。 第 04 课整节都在讲改这个阈值的后果。
  • 置信度带：p=0.25 与 p=0.75 两条虚线。 夹在中间的区域是模型拿不准的地方。

决策边界一定是直线，原因在公式里：p=0.5 等价于 z=w1​x1​+w2​x2​+b=0， 而这是一个关于 x 的一次方程。sigmoid 是单调函数，它只改变颜色的深浅， 不改变边界的形状。所以「同心圆」那份数据无论怎么训练都分不开—— 正确的边界是一个圆，而这个模型只会画直线。

w 的长度控制的是过渡带的宽度

把 (w,b) 整体乘以 k，决策边界一点不动， 因为 kw⊤x+kb=0 和 w⊤x+b=0 是同一个方程。变的是颜色的陡峭程度。 这个宽度可以算出来：从 p=0.25 走到 p=0.75，z 要变化 2ln3≈2.197， 而沿着 w 的方向每走一个单位 z 就变化 ∥w∥，所以两条虚线之间的距离是 2ln3/∥w∥。

在演示里把 w1​ 设成 1.00、w2​ 设成 0.00、b 设成 0，边界就是竖线 x1​=0， 两条虚线的间距是 2.2 个刻度。再把 w1​ 改成 4.00，b 仍然是 0 所以边界不动，间距缩到 0.55。可以对着坐标轴量一下。

注意只改 w 而不动 b 时边界会移动： 它到原点的距离是 ∣b∣/∥w∥。 上面那组数字之所以干净，是因为 b 恰好取了 0。

还有一件事值得注意：准确率和 BCE 衡量的不是同一件事。 把 w1​,w2​,b 三个数同时乘以 10，决策边界一动不动， 准确率一个百分点都不变，但 BCE 会明显变化——所有分对的点损失更小， 所有分错的点损失暴涨。准确率只看点落在边界的哪一侧，BCE 还要看模型有多确信。 训练时优化的是 BCE，验收时看的往往是准确率，两者不一致是很多困惑的来源。

第一步：为什么不能直接拿线性回归做分类。 把标签编码成 0 和 1，再用 MSE 拟合，会遇到两个问题。 一是 y^​=wx+b 的取值没有上下界， 算出 1.7 或者 −0.3 都很正常，这种数当概率用没有意义。 二是就算在后面套上 sigmoid 再用 MSE，损失关于参数不再是凸函数， 而且梯度会在最需要它的地方消失。

第二点值得算一个具体数字。设某个样本真实标签 y=1， 而模型给出 z=−8，也就是错得非常离谱。此时 σ(−8)=3.35×10−4。

两者相差约 1500 倍。用 MSE 时，一个彻底判错的样本几乎推不动参数， 因为多出来的 σ(1−σ) 因子在饱和区趋于 0； 用交叉熵时，这个样本会被结结实实地罚一下。这就是分类不用 MSE 的实际理由。

第四步：损失从哪来。 交叉熵不是拍脑袋定的，是最大似然推出来的。 模型对第 i 个样本给出的概率是 pi​， 那么它认为「真实标签恰好是 yi​」这件事的概率可以写成一个式子：

假设样本之间独立，整份数据的似然（likelihood）是连乘。连乘不好优化， 取对数变成连加，再取负号把「最大化」变成「最小化」，最后除以 n 让损失与样本量无关。这条路线叫最大似然估计（maximum likelihood estimation）：

这就是二元交叉熵（binary cross-entropy，BCE）。 它对每个样本只看一件事：模型给正确答案分配了多少概率。 分配得越少，−log 罚得越狠，而且是无上界地狠。

上面第二个式子里被约掉的 p(1−p) 是关键。 交叉熵对 p 的导数分母上带一个 p(1−p)， sigmoid 对 z 的导数分子上带一个 p(1−p)， 两者相乘正好约干净。换任何一个搭配都不会这么整齐： sigmoid 配 MSE 会留下一个 p(1−p) 因子， 于是饱和区梯度消失，也就是本节开头算的那 1500 倍差距。

这个约分不是逻辑回归独有的。softmax 配交叉熵（多分类）、 以及第 13 课 Transformer 输出层用的 softmax，梯度都是同样的(p−y)x 形式。所以框架才会把这两步打包成一个算子， 比如 PyTorch 的 BCEWithLogitsLoss 和 CrossEntropyLoss。

第六步：别照着 BCE 的定义式写代码。 公式里的 logp 在数值上是个坑。 float64 下 z 大到 37 左右，σ(z) 就被舍入成精确的 1.0，于是 log(1−p)=log0=−∞， 损失变成 nan。float32 下这个临界值只有 17 左右，更容易撞上。

把定义式恒等变形一下，问题就消失了：

本站演示里的 bceLoss 用的就是这个形式，所以你把 w 拖到很大时读数依然正常。

第七步：线性可分时会出什么事。 如果两类点能被一条直线完全分开，那么把 (w,b) 整体乘以 k>1，每个点的 p 都更靠近正确的那一端，BCE 严格下降。 于是最优解在无穷远处：∥w∥ 会一直增大，损失趋于 0 但取不到。 演示里选「线性可分」数据、把 λ 设为 0 再训练， 就能看到 ∥w∥ 读数一路上涨而边界方向早已不动。

加一项 λ∥w∥2 就能止住它： 权重再大要付出代价，最优解重新变得有限。这也是 sklearn 默认就开着 L2 的原因。 正则化（regularization）本身是第 05 课的主题，这里只需要知道它在这个具体场景里解决了什么。

把这一课的失效条件列全：特征和标签之间不是「一条直线两侧」的关系时（同心圆、异或）， 准确率会停在接近瞎猜的水平，换优化器和学习率都没用；两类完全分得开且不加正则时， 参数没有有限的最优解；两个特征的量纲差很多时（比如一个是「元」、一个是「年」），λmax​(M) 被大尺度那一维撑大， 上面那个稳定学习率会被压得很小，收敛会慢到看不出在动，先做标准化再训练。

从公式到代码

先把公式一比一抄成 NumPy。注意 err = p - y 这一行， 它就是上面推出来的 ∂L/∂z， 后面全部梯度都是从它乘出来的。

实际工作里没人手写这段。sklearn 一行就能拟合，但有一个默认值必须知道： 它默认带 L2 正则，强度由 C 控制，而 C 是正则强度的倒数。

PyTorch 版本里，nn.Linear(2, 1) 只输出 z，不带 sigmoid。 概率只在需要看结果时才算。

为什么是 BCEWithLogitsLoss，不是 Sigmoid + BCELoss

两条路数学上等价，数值上不等价。nn.Sigmoid() 加 nn.BCELoss() 会先把 z 变成 p，再算 logp。float32 下 z 超过约 17，p 就被舍入成 1.0，log(1−p) 应该是 −∞。 PyTorch 的 BCELoss 为了不让程序崩掉，会把 log 的结果截断在 −100， 于是你拿到的不是报错，而是一个封顶的假损失和一个错误的梯度——训练悄悄跑偏，没有任何提示。

BCEWithLogitsLoss 直接用 ζ(z)−yz 这个等价形式，中间不出现会溢出的量，梯度也直接是 σ(z)−y。多分类的 CrossEntropyLoss 同理，它接收的也是 logits 而不是概率。 这条规则可以直接背下来：损失函数收 logits，不收概率。

自己试试

自己试试

  1. 1
    把数据集切到「同心圆」，点训练跑三四百步，看准确率停在哪、‖w‖ 变成多少。
    准确率停在 50% 到 65% 之间（默认这份停在 60.0%），点一次「重新采样」它就换一个数——这几个百分点是蒙对的，不是学到的。同时 ‖w‖ 会从初始的 1.03 掉到 0.2 上下（默认这份是 0.16），BCE 停在 0.6762，只比「处处输出 0.5」对应的 ln 2 = 0.6931 低一点点。直线模型在这份数据上能做的就这些，换特征或换模型才有用，换优化器没用。
  2. 2
    手动把 w₁ 设成 1.00、w₂ 设成 0.00、b 设成 0，再对着横轴量两条虚线的间距。
    间距是 2ln3/‖w‖ ≈ 2.2 个刻度。把 w₁ 改成 4.00，间距缩到 0.55，而边界仍是 x₁ = 0。‖w‖ 控制的是概率过渡得有多陡。注意这个干净结论依赖 b = 0：b 不为 0 时只调 w，边界到原点的距离 |b|/‖w‖ 会跟着变。
  3. 3
    用「线性可分」数据、λ = 0，点「重置」把参数归零，再点训练，盯住 ‖w‖ 这个读数。
    按默认设置（n=120，η=0.5），50 步时 ‖w‖≈2.20，100 步 ≈2.58，200 步 ≈2.99，400 步 ≈3.42，1000 步 ≈4.03：步数翻倍，‖w‖ 只加约 0.42，但一直不停。把 λ 调到 0.05 再重置训练，‖w‖ 五十步内就锁在 1.23 不动了，准确率仍然是 100%。
  4. 4
    先训练到边界摆正，再把「点空白处添加哪一类」切到类别 0，在右上角 (5, 5) 附近那片蓝色区域里点三个点，然后继续训练。
    边界的方向几乎不动（实测只转了一度左右），那三个点到最后仍然被判成类别 1（p ≈ 0.999），红圈一直挂着。真正明显变化的是 ‖w‖：实测从 3.0 掉到 1.0 附近，两条虚线之间的过渡带宽了约三倍——模型没有被拽过去，只是不再那么笃定。原因是单个样本对梯度的贡献是 (p−y)·x，而 |p−y| < 1 有界，一个点最多贡献 |x|。对比上一课：线性回归里一个离群点就能把整条直线拉走，因为平方误差对残差没有上界。
  5. 5
    刷新页面，把学习率滑块拉到最右（η = 20），先在「线性可分」上点单步几次，再换到「同心圆」上跑训练。
    线性可分那份：从刚打开页面的默认参数起，第一步 BCE 就从 1.3721 冲到 11 左右，‖w‖ 一步从 1.03 跳到 35。第二步之后所有点都判对了，但每个点的 |z| 都超过 18，全部进了 sigmoid 的饱和区，梯度掉到 1e-10 量级，BCE 读数变成 0.0000，参数从此一动不动。它确实把这份数据分开了，但停下来的原因是梯度被饱和压没了，不是走到了最优——线性可分时最优解本来就在无穷远。同心圆那份则是 BCE 在 4 和 16 之间来回跳，永远不收敛。面板上那个上限是 2/L，其中 L = λ_max(M)/4 是 BCE 的光滑常数、M 是数据的二阶矩矩阵；η 低于它一定收敛，超过它就是上面这两种失控之一。

延伸

这一课要带走的一句话

逻辑回归输出的是概率，不是类别；类别是你自己拿阈值切出来的。

另外记住梯度那个形式：n1​∑(pi​−yi​)xi​。 它和线性回归一模一样，往后到 softmax、到语言模型的输出层都是这个样子。 下一课专门讲阈值：同一个模型，阈值从 0.5 挪到 0.2，召回率上升、误报率也上升， 准确率可能反而下降。哪个阈值合适，取决于漏判和误判各自的代价，模型本身给不出答案。
